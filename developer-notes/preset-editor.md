# Preset packs and keyboard mapping

Settings remains fully native: AppKit `NSSplitViewController` owns the titlebar, divider, collapse behavior, and `NSTableView` sidebar; SwiftUI renders the content. Set Management is a flat list. Clicking anywhere in a set row, including its name, opens a single page with its image presets above its keyboard mappings. There is no nested mapping child or separate pack card screen. The divider resizes the sidebar (190–340 points), its hit area is widened for easier dragging, and the toolbar toggles it. Native window controls occupy their own titlebar. Sidebar selection supports keyboard navigation, and dragging sets reorders the persisted list.

Use Set explicitly changes the desktop pet; selecting or editing an inactive set does not. The active set and built-in set cannot be deleted from the list. New Set opens a native popover from the sidebar plus button, asks for a unique name, and creates an empty, inactive set. Add Images opens the native file picker. The first image fills both default typing and resting reactions; empty sets cannot be used. Duplicate creates and selects a uniquely named editable set, copying every preset image into its own directory, including migrated key-reaction images. It preserves names, selections, ordering, and modifier mappings without activating the copy or sharing future edits.

Each pack owns freely named image presets, exact physical key mappings with any combination of Control, Option, Shift, and Command, and independent Unassigned and IDLE selections. Each selection supports random or sequential playback. Random playback avoids repeating the last image when alternatives exist. Sequential playback follows the selected order.

The default typing and resting reactions appear above the keyboard (Korean: “입력 중일 때”, “쉬고 있을 때”). Clicking either card, a keyboard key, or the Space/Enter quick setup buttons opens one native `NSPopover`. Anchor rectangles are measured after key sizing in the scroll viewport coordinate space, so the tail meets the edge of the clicked key or quick button and follows scrolling. The hosting content is measured before presentation; automatic hosting-size propagation is disabled, and content-height changes explicitly remeasure and reposition the same popover. Its hosting controller remains independent of the changing key thumbnails, so preset selection, autosave, mode changes, and ordering keep it open. Outside clicks and Escape dismiss it. Modifier keys use checkboxes and a multiple-selection hint. Space and Enter share the exact modifier layer and mappings used by the physical keyboard controls. No inline accordion, preview mode, key-capture mode, editing-pack bar, or save button remains. Arrow keys use a real inverted-T cluster, with Up above Down and Left/Right aligned to the bottom. The keyboard stays 760 points wide with fixed key proportions; a horizontal scroll view handles narrower content panes. Gallery image editing uses a separate view in the same single popover owner.

All edits save atomically as they are made. Active-pack edits reload the desktop pet immediately. Custom-pack images can be added, replaced, renamed, and deleted in the gallery. The built-in pack gallery is read-only: image additions, replacements, deletions, and preset renames are blocked in both the editor and store. Its key mappings, Unassigned and IDLE selections, and playback modes remain editable. Explicit Restore Defaults still restores the bundled presets. Deleting a preset removes its references from key mappings; a mapping with no remaining presets falls back to Unassigned. If the only Unassigned or IDLE preset is deleted, the confirmation requires choosing a replacement. The active pack's last image cannot be deleted; an inactive pack may become empty. Original and imported image files remain on disk.

General displays the current macOS Input Monitoring authorization separately from the event tap connection. It refreshes while visible and when the app becomes active. Check Again reads authorization and retries the event tap only when already authorized. Open System Settings uses the existing permission guide. This UI never grants permissions or requests Accessibility access.

## Persistence and compatibility

Pack configurations are stored atomically in `Images/packs-v1.json` under the current profile's Application Support directory. Development and production remain separate. Existing image sets become packs on first load. Existing global key rules are preserved in every existing pack, referencing their existing copied images. New empty packs start without those mappings. Unreadable or future-version pack documents are preserved and cannot be overwritten by the editor.

Original image-set metadata and legacy key rules remain available; migration deletes no source files. The desktop pet, menu image replacements, and settings share one `PetPackStore` and `PresetPlaybackCursor`. The desktop pet requires Input Monitoring for keys pressed in other apps.
