# 팩 교환 API와 로컬 개발

버전: **0.20.0**

앱은 `https://pet.miel.ing/share-api`에 자동 연결한다. 사용자가 서버 주소를 입력할 필요는 없다. Mac mini에서 전용 API가 `127.0.0.1:17868`에 바인딩되고 nginx가 HTTPS 요청을 전달한다. 웹사이트와 앱 업데이트 호스트는 기존 경로를 유지한다.

## 사용자 흐름

`설정 → 세트 관리 → 공유 · 가져오기`에서 공유, 코드로 받기, 받은 템플릿, 공유 관리를 제공한다.

- 공유는 당시 팩의 독립 사본을 v1으로 게시한다. 제작자의 한마디는 선택 사항이며 500자 이내다.
- 6자리 대문자·숫자 코드와 별도의 무작위 관리 비밀번호를 발급한다. 비밀번호는 발급 화면에서 별도로 보관해야 한다. 앱이 영구 저장하지 않으며 분실 복구를 제공하지 않는다.
- 관리 화면은 제작자의 원래 로컬 팩이 없어도 코드·비밀번호로 동작한다. 선택한 로컬 팩을 새 버전으로 게시하며, 기준 버전이 오래되었으면 충돌을 알린다.
- 받은 템플릿은 기존 팩 목록과 별도 저장한다. `내 로컬 팩으로 복사` 후 기존 `사용하기` 동작으로 적용한다.
- 업데이트는 템플릿을 교체한다. 이미 복사한 팩, 사용 중인 펫, 로컬 편집은 변경하지 않는다. 최신 버전을 사용하려면 새 로컬 사본을 만든다.
- 공유 삭제는 새 조회·다운로드·업데이트를 중단한다. 기존 템플릿과 로컬 사본은 계속 사용할 수 있다. 삭제된 코드는 재사용하지 않는다.

## 로컬 개발

```sh
./scripts/run_share_dev.sh
```

`uv`로 잠긴 Pillow 의존성을 설치한다. 기본 상태 경로는 `~/Library/Application Support/TypingPetDev/ShareService/`이다. 앱 기본값은 공개 서비스이므로 로컬 테스트 때만 개발 프로세스에 다음 환경변수를 전달한다.

```sh
TYPINGPET_SHARE_API_URL=http://127.0.0.1:17868 swift run
```

프로덕션 앱은 이 환경변수로 주소를 변경하지 않는다. 개발 앱만 HTTPS 또는 루프백 HTTP 재정의를 허용한다.

## API

| 메서드와 경로 | 기능 |
|---|---|
| `GET /health` | 서비스 상태·버전 |
| `POST /v1/shares` | 공유 생성, 코드·관리 비밀번호 발급 |
| `GET /v1/shares/{code}` | 최신 메타데이터·한마디·크기·해시 |
| `GET /v1/shares/{code}/versions/{revision}` | 특정 불변 버전 다운로드 |
| `GET /v1/shares/{code}/versions/latest` | 기존 개발 클라이언트 호환 다운로드 |
| `POST /v1/shares/{code}/versions` | 새 버전 게시 |
| `DELETE /v1/shares/{code}` | 공유 삭제 |

생성은 `X-Request-ID`, `X-Request-Secret`이 필요하다. 같은 요청과 패키지로 재시도하면 같은 코드·비밀번호를 반환한다. 앱은 공유 패널이 열린 동안 실패한 생성의 패키지와 재시도 정보를 유지한다. 앱 종료 후 자동 복구는 제공하지 않는다. 관리 요청은 `X-Share-Password`, 새 버전 게시는 `X-Base-Version`을 사용한다. 비밀번호·요청 비밀값은 URL이나 로그에 기록하지 않는다.

코드는 난수 키 기반 HMAC으로 생성하며 DB 유일성 제약으로 충돌을 처리한다. DB에는 코드 조회 HMAC과 salt가 있는 PBKDF2 비밀번호 해시를 저장한다. 생성 재시도 결과는 서버 키와 요청 비밀값으로 재구성하므로 비밀번호 평문을 DB에 보관하지 않는다. `lookup.key`는 복구에 필수인 서비스 상태다.

ZIP 루트에는 `manifest.json`과 `images/`가 있다. manifest는 `format`, `formatVersion`, `name`, `configuration`, `images`, 선택적 `creatorMessage`를 포함한다. 저장 형식 버전과 콘텐츠 게시 버전은 별개다.

## 운영 경계

공개 서비스는 전용 API 프로세스와 HTTPS 프록시로 운영한다. 이미지와 저장 용량·요청 한도를 적용하며, DB·조회 키·버전 패키지를 일관되게 백업한다. 구체적인 설치 경로와 복구 기록은 운영 환경의 비공개 문서에서 관리한다.

공유 코드는 코드 소지자가 접근할 수 있는 배포 수단이며 비공개 저장소나 계정 기반 접근 통제를 제공하지 않는다. 삭제된 공유의 서버 패키지는 제거되지만 이전 백업에는 보존 기간 동안 남을 수 있다.

앱은 ZIP 경로·파일 종류·중복·실제 압축 해제 크기·CRC를 검사하고 이미지와 SHA-256을 확인한 뒤 템플릿을 설치한다. 운영체제 압축 해제 도구로 링크나 파일 메타데이터를 복원하지 않는다. 템플릿 설치 실패 시 기존 템플릿을 보존한다. 서버는 Pillow로 이미지도 검사한다.

## 검증

```sh
scripts/share-service/.venv/bin/python scripts/test_share_service.py
swift test
TYPINGPET_TEST_SHARE_HTTP=1 TYPINGPET_SHARE_API_URL=http://127.0.0.1:17868 swift test --filter ShareExchangeTests
```

마지막 명령은 실제 HTTP 생성·받기·로컬 복사·수정·업데이트·삭제를 수행한다. 공개 주소로도 같은 검증을 할 수 있다. 생성한 테스트 공유는 테스트 완료 시 삭제한다. 자동화 성공은 다른 사용자의 Mac에서 직접 사용한 결과나 재부팅 복구 검증을 의미하지 않는다.

2026-11-05에는 공개 HTTPS API를 포함한 앱 테스트 124개, 독립 서비스 테스트 5개가 통과했다. 실제 개발 앱에서도 코드 입력·템플릿 받기·업데이트·로컬 복사를 확인했다. 앱의 공증·정식 릴리스와 재부팅 복구 검증은 별도다.
