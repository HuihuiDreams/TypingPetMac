## 발행 기준

1. **초안은 따로 관리합니다.** 저장소 루트의 `docs/`는 Git에서 제외하는 로컬 기획·작업 공간입니다. 자동 복사나 배포 원본으로 사용하지 않으며, 필요한 백업과 공유는 별도로 관리합니다.
2. **공개 글로 편집합니다.** 문제, 현재 동작, 설계 근거, 한계와 검증 결과를 중심으로 씁니다. 대화 기록·개인 작업 목록·내부 운영 정보는 공개 원고에서 정리합니다. 공개되지 않은 초안을 디렉터리째 옮기지 않습니다.
3. **상태와 근거를 표시합니다.** 설계 검토에는 작성·수정일과 미구현 상태를 적고, 확정된 동작과 후보를 구분합니다. 기술 설명은 관련 코드·공식 자료를 연결하고, 검증하지 않은 동작은 명시합니다. 가격·한도·API 조건은 발행 시점에 다시 확인합니다.
4. **기존 글도 관리합니다.** 동작이 바뀌면 해당 안내를 함께 수정합니다. 설계가 채택·보류·폐기되면 상태와 이유를 갱신합니다. 새 노트는 이 목차에 등록하고, 파일명은 소문자와 하이픈을 사용합니다.
5. **공개 범위를 확인합니다.** 로컬 링크와 이미지, 공개 가능한 원고·자산인지 확인하고 Git diff를 검토한 뒤 커밋·게시합니다. 개인 키·토큰·자격 증명·개인정보와 미공개 초안은 포함하지 않습니다.

개발 노트는 GitHub 저장소에서 공개합니다. 홈페이지의 [패치 노트 소스](../website/src/releases.json)와 [앱 변경 기록](../CHANGELOG.md)은 릴리스 변경 사항을 별도로 관리합니다. 개발 노트 수정만으로 앱이나 홈페이지가 배포되지는 않습니다.
