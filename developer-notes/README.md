## 文档规范

1. **草稿单独管理**：仓库根目录的 `docs/` 为本地规划和工作空间（Git 已忽略）。不作为自动同步或发布的源文件，备份和共享单独处理。
2. **整理为公开文档**：重点阐述背景痛点、当前行为、设计依据、限制条件与测试验证结果。对话记录、个人待办列表和内部运维数据不放入公开稿件。
3. **标明状态与依据**：设计评审文档需标注撰写/修订日期及未实现状态，区分既定方案与备选构想。技术描述需链接到相关代码和官方文档，未经测试的行为需明确注明。
4. **同步维护既有文档**：功能逻辑变更时需同步更新对应文档。方案被采纳、搁置或废弃时及时更新状态与理由。新笔记在此目录索引中登记，文件名使用小写字母和连字符。
5. **安全与隐私检查**：检查外链、图片及公开内容的合规性，在审查 Git diff 后再提交和发布。严禁提交私钥、Token、敏感凭证或未公开敏感草稿。

开发笔记在 GitHub 仓库中开源维护。官网的 [更新日志数据](../website/src/releases.json) 与 [CHANGELOG.md](../CHANGELOG.md) 独立管理版本更新记录。仅修改开发笔记不会触发应用或官网发布。
